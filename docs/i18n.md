# Translations

lotse is translated with gettext: English msgids in the source, a German catalogue (`de`) next to
them. The design is in [ADR 0005](adr/0005-two-gettext-domains.md).

## Domains

| Domain | Catalogue | Source scanned | Holds |
|---|---|---|---|
| `eu.jumplink.Lotse` | `app/po/` | `app/src` | the window, Preferences, the CLI, notifications |
| `lotse` | `packages/widget/po/` | `packages/core/src`, `packages/widget/src` | the chat widget and core's sentences |

Log messages and protocol strings stay English and are not wrapped.

## Workflow

```sh
./dev/i18n.sh extract     # refresh both .pot files and merge into every .po
./dev/i18n.sh compile     # build app/dist/locale/<lang>/LC_MESSAGES/<domain>.mo
npm run check:i18n        # fails on an untranslated or fuzzy msgid
```

In code: `_('text')`, `_n('{n} x', '{n} xs', n)`, `_p('context', 'text')`, `fmt(template, values)` for
`{name}` placeholders, and `N_('text')` to mark an exported constant that is translated at use.
Translate where the string is built, never at module level.

## Status

| Language | `eu.jumplink.Lotse` | `lotse` |
|---|---|---|
| German (`de`) | complete | complete |

`check:i18n` keeps it that way. German uses the informal "du" form.

## Testing

- `app/tests/unit/i18n.test.ts` covers the identity fallback, placeholders and plurals (Node and GJS).
- `npm run test:i18n` (in `app/`) compiles the catalogues and checks, under `LANGUAGE=de`, that both
  domains render German.

## Hosts

An app that embeds the widget gets its translations as described in [embedding.md](embedding.md#translations).
